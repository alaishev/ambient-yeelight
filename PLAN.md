приложение тоже работает.

## Проверка

- [ ] 19. Пройти по всему коду и найти неочевидные места: скрытые переходы управления, гонки,
  порядок запуска и остановки, состояние, которое меняется не там, где его ждёшь. Алгоритм везде

  Заодно имена функций-действий глаголами: `notification()` → `createNotification()`,

  `findDominantColor()`, `priority()` → `toPriority()`.
  Убрать ссылки `[name]` из комментариев: обычный текст, см. CLAUDE.md.

## Частота команд

- [ ] 21. Пауза между кадрами отсчитывается от начала прошлого кадра, а не от конца обработки:
  тогда интервал из настроек (по умолчанию 300 мс) соблюдается точно. Переход `smooth` по
  умолчанию 300 мс: на ленте при трёх цветах в секунду смотрится плавно. На обычном соединении
  лимит 144 команды в минуту (одна в 417 мс), при долгой динамичной сцене часть цветов пропадёт;
  в music mode лимита нет.
- [ ] 22. Лимит 60 команд на соединение считать за последние 60 секунд, а не за всё время
  соединения: в спокойных сценах соединение не переоткрывается.

## Отложено

В последнюю очередь, когда будет возможность проверить на ленте.

- [ ] 12. `ColorExtractor`: доминирующий цвет, яркость по картинке, приглушение в тёмных сценах.
  На экран настроек: следование яркости, минимальная яркость.
  Что известно:
  - лампа берёт из `set_rgb` только оттенок, яркость задаёт `bright`: тёмно-серый на ленте —
    белый;
  - самый частый цвет кадра часто приходится на полосы и рамки, а не на картинку;
  - в CIE76 светлота L умножена на 2.55, из-за этого тёмные цвета мигают через фильтр ΔE;
  - варианты: выбирать группу Palette по площади и насыщенности без тёмных; яркость — средняя
    светлота кадра, одной командой с цветом (`start_cf`) или `set_bright` по изменению.
- [ ] 18. Зоны экрана для ламп: перед началом обсудить логику и UI выбора зоны, разбить на подпункты.

После всех пунктов: один раз собрать проект и проверить lint.
